FIX

인증 코드 확인의 시도 횟수 제한 우회 수정

날짜: 2026-11-08커밋: 94760a1

문제 분석

원인

EmailVerificationService.confirm이 코드를 읽고 비교한 뒤에 실패 횟수를 세었다. 삭제는 그 다음이라, 동시에 들어온 요청이 모두 비교 단계를 통과했다.

영향

6자리 코드(100만 가지)를 5회 제한 없이 추측해 남의 이메일로 인증을 통과하고 가입할 수 있었다.

놓친 이유

테스트가 순차 호출과 Fake store만 써서, 동시 요청에서만 깨지는 확인 후 처리(check-then-act) 구조를 재현하지 못했다. 코드를 쓴 쪽의 단일 요청 가정이 리뷰 전까지 남았다.

재발 방지

시도 횟수를 비교 전에 원자적으로 올린다. 한도 소진 상태를 Fake로 만들어 맞는 코드도 거절되는지 보는 회귀 테스트를 추가했고, CLAUDE.md에 동시성 규칙과 PR 전 리뷰 절차를 넣었다.

    public void confirm(String rawEmail, String input) {        String email = User.normalizeEmail(rawEmail);        VerificationCode code = store.findCode(email)                .orElseThrow(() -> new BusinessException(ErrorCode.VERIFICATION_EXPIRED));        // 비교보다 먼저 시도 횟수를 원자적으로 올린다. 읽고 비교한 뒤에 세면 동시 요청이 모두        // 비교를 통과해서 한도를 넘겨 코드를 추측할 수 있다.        long attempt = store.recordAttempt(email);        if (!code.hasAttemptLeft(attempt)) {            store.deleteCode(email);            throw new BusinessException(ErrorCode.VERIFICATION_ATTEMPTS_EXCEEDED);        }        if (code.matches(input)) {            store.deleteCode(email);            store.markVerified(email);            return;        }        if (code.isExhausted(attempt)) {            store.deleteCode(email);            throw new BusinessException(ErrorCode.VERIFICATION_ATTEMPTS_EXCEEDED);        }        throw new BusinessException(ErrorCode.INVALID_VERIFICATION_CODE);

# Market Research

비슷한 서비스를 조사해, **시장에서 확인된 사실**과 **이 앱에 필요한 것**을 근거와 함께 나눠 보여준다. 결과물은 아래 계약을 따르는 문서 한 개다.

## 산출물

- 경로: `docs/market-research/YYYY-MM-DD-<주제>.md`
- 문서가 git에 올라가지 않도록 `.git/info/exclude`에 `docs/market-research/`가 없으면 추가한다. (설계 문서는 추적하지 않는 것이 이 프로젝트 방침)
- 마지막에 대화로는 "지금 필요한 것 Top 3"와 파일 경로만 알려준다.

## 작성 순서 (문서의 섹션 순서와 같다)

1. **전제** — 개인용인지 공개 서비스인지, 사용자 규모, 제약(1인 개발, Spring/PostgreSQL, Render 무료 플랜). 저장소 루트와 `docs/`에서 `PRODUCT.md`를 Glob으로 찾고, 있으면 읽어서 옮긴다. 없을 때만 가정이라고 적는다.
2. **우리 앱 현황** — `presentation/controller`와 `domain/*` 코드만 읽고 기능 표를 만든다(기능 / 근거 파일). `docs/superpowers/`의 스펙·계획은 읽지 않는다. 설계가 계속 바뀌어 현재 기능의 근거가 되지 못한다. 각 핵심 엔티티(`Application`, `Schedule`, `Interview`)와 상태 enum은 소스를 열어 필드를 표에 적는다. 이 필드 목록이 5번 제안의 "이미 있음/없음" 판단 근거다. 프론트엔드는 별도 저장소이므로 "프론트에서만 있는 기능은 미확인"이라고 적는다.
3. **시장 현황** — 서비스 6개 이상: 해외 트래커 3개 이상(Huntr, Teal, Simplify, Careerflow 등)과 국내 서비스 3개 이상(사람인, 잡코리아, 원티드, 잡플래닛, 링커리어 등 지원·면접 관리 기능이 있는 것). 서비스마다 **공식 페이지를 직접 열어** 확인한 기능만 적는다. 홈 화면에 기능 설명이 없으면 WebSearch로 그 서비스의 기능·도움말 페이지 URL을 찾아 그 페이지를 연다. 열린 페이지에 기능 설명이 한 줄도 없거나 페이지가 열리지 않으면(403, ENOTFOUND 등) 그 서비스를 같은 구분(해외/국내)의 다른 서비스로 바꿔 "기능을 확인한 서비스" 수로 목표 개수를 채우고, 바꾼 서비스는 7번에 적는다. 한 줄마다 `출처 URL (조회일)`을 붙인다. 블로그·제휴 비교글은 "2차 출처"로 표시한다.
4. **기능 비교표** — 행은 기능, 열은 우리 앱 + 각 서비스. 칸은 ○ / × / 미확인.
5. **기능 격차 피드백** — 격차 하나당 아래 블록 하나. 4번 표에서 시장에 ○인데 우리 앱이 ×인 기능만 쓴다.
   - **시장:** `<서비스명>`에 `<기능>`이 있다. (3번의 출처 URL, 조회일)
   - **우리 앱:** 이 기능이 없다/부족하다. (2번의 근거 파일·필드)
   - **있으면 도움이 되는 이유:** 취업 준비자가 겪는 구체적 상황 한 문장.
   - **규모 / 구현 경로 / 우선순위:** S·M·L, 이 스택에서의 경로(예: 기존 Gmail 발송 재사용, enum 확장, 마이그레이션 필요 여부), 높음·중간·낮음.
6. **지금 이 앱에 필요한 것** — 5번 블록 중 Top 3(기능명 + 한 줄 이유). 이어서 "시장에 있지만 하지 않을 것"과 이유(현재 제약 기준), "우리 앱에만 있는 것"(시장 표에서 우리만 ○인 기능).
7. **미확인 목록** — 열어보지 못한 페이지, 서로 어긋난 수치, 추정으로 쓴 문장.

## 도구

- 검색·페치 도구가 deferred 상태이면 `ToolSearch`로 `WebSearch`, `WebFetch`를 먼저 로드한다.
- 쓸 수 있는 웹 도구가 없으면 문서 맨 위에 "웹 확인 불가, 일반 지식 기반"이라고 적고 3번의 모든 주장을 "미확인"으로 표시한다.

## 빠른 모드

요청에 "빨리", "간단히"가 있으면 목표를 "기능을 확인한 서비스" 해외 2개 + 국내 2개로 줄인다. 7개 섹션, 2번의 엔티티 소스 열람, 3번의 기능 페이지 검색·열람, 출처·조회일은 그대로 둔다. 문서 길이는 각 섹션을 짧게 쓰는 것으로 줄인다.

## 자주 하는 실수

| 실수 | 올바른 형태 |
|---|---|
| 검색 결과 요약만 보고 기능을 적음 | 공식 페이지를 열어 확인한 것만 3번에 적고, 나머지는 미확인 |
| 출처 URL만 있고 날짜가 없음 | 모든 줄에 `(조회일)` |
| 시장 사실과 내 의견이 섞임 | 3~4번은 사실, 5~6번은 제안으로 섹션을 나눔 |
| 시장 근거 없는 코드 품질 지적(DTO, 페이지네이션 등)을 5~6번에 섞음 | 5번은 시장에서 확인된 기능 격차만. 코드 품질 피드백은 사용자가 요청했을 때만 8번 부록으로 |
| 해외 서비스만 조사 | 국내 서비스 3개 이상 포함 |
| 서비스 하나가 403이라 목표 개수를 못 채움 | 같은 구분의 다른 서비스로 교체 |
| 엔티티 소스를 안 열고 "필드 미확인"으로 제안 | 2번에서 필드 목록을 확정한 뒤 제안 |
| 스펙·계획 문서의 기능 목록을 현재 기능으로 적음 | 있다/없다 판단은 코드 기준. `PRODUCT.md`와 코드가 다르면 코드를 따름 |
